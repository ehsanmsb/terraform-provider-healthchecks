# healthchecks_integration (Resource)

Manages a project notification integration (Healthchecks channel). The current provider supports `webhook`, `email`, and `ntfy` integrations through authenticated web form endpoints.
## Example Usage

```terraform
resource "healthchecks_project" "example" {
  name = "Integrations Project"
}

resource "healthchecks_integration" "webhook" {
  project_id      = healthchecks_project.example.id
  project_api_key = healthchecks_project.example.api_key
  type            = "webhook"
  name            = "Primary Webhook"

  webhook = {
    method_down = "POST"
    url_down    = "https://example.com/down"
    body_down   = jsonencode({ state = "down" })
    headers_down = {
      X-Sample-Header = "$NAME has gone down"
      X-Env           = "production"
    }
    method_up = "POST"
    url_up    = "https://example.com/up"
    body_up   = jsonencode({ state = "up" })
    headers_up = {
      X-Sample-Header = "$NAME has recovered"
      X-Env           = "production"
    }
  }
}

resource "healthchecks_integration" "email" {
  project_id      = healthchecks_project.example.id
  project_api_key = healthchecks_project.example.api_key
  type            = "email"

  config = {
    value = "alerts@example.com"
    down  = "true"
    up    = "false"
  }
}

resource "healthchecks_integration" "ntfy" {
  project_id      = healthchecks_project.example.id
  project_api_key = healthchecks_project.example.api_key
  type            = "ntfy"

  ntfy = {
    url         = "https://ntfy.example.com"
    topic       = "production"
    priority    = 4
    priority_up = 2
    token       = var.ntfy_token
  }
}

variable "ntfy_token" {
  type      = string
  sensitive = true
  default   = null
}
```

## Notes

- Set `project_api_key` from `healthchecks_project.<name>.api_key` so the provider can identify the new channel during apply.

- Use `type = "webhook"` for HTTP callbacks on up/down events.
- Webhook integrations support the optional top-level `name` attribute and the structured `webhook` block.
- Webhook request headers can be configured with `webhook.headers_down` and `webhook.headers_up` as maps of header names to values.
- Header maps are translated into the newline-delimited `Header-Name: value` format expected by the Healthchecks webhook form.
- The legacy `config` map is still accepted for webhook integrations, but the `webhook` block is the preferred interface.
- Use the legacy `config` map only when you need backward compatibility with older provider versions.
- Use `type = "email"` with `config.value` set to the destination email address. Omit `name` and `webhook` for email. The `config.up` and `config.down` flags default to `"true"` when omitted.
- Use `type = "ntfy"` with the `ntfy` block. Set the server URL and topic, and optionally set down/up priorities and an access token.
- Changing an integration's `type` replaces the channel and produces a new channel ID.
- Integrations become active for a check when their channel ID is referenced in `healthchecks_check.channels`.
